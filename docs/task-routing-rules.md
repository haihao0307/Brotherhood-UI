# 任务路由规则

这份文件决定“什么任务 -> 哪个状态 -> 哪个英雄”。

`route_task.py` 现在按“强关键词 -> 常规关键词 -> 弱关键词”的方式计分：
- 先把用户任务转成小写，并把连续空白压成一个空格
- `strong_keywords` 命中时分值最高，优先决定 demo prompt 和高价值短句
- `keywords` 是常规命中词，负责日常覆盖
- `weak_keywords` 只做补强，不能单独决定最终规则
- `exclude_keywords` 一旦命中，会把当前规则排除，避免宽词误触
- 如果短关键词被更长短语完整覆盖，只按更长短语记分一次
- 长度过短的宽词会被自动降权；低分命中不会强行落到某个 worker

所以这份文件的核心目标不是“写得漂亮”，而是：
- 尽量覆盖你们日常跟龙虾对话的真实说法
- 尽量把容易混淆的任务拆开
- 让状态和英雄分配稳定，不要同一句话今天匹配吴用、明天匹配武松

### 维护规则
- 每条规则都从 `## 规则名` 开始
- 每条规则必须包含：
  - `hero`
  - `state`
  - `detail`
  - `keywords`
- 每条规则可以按需补充：
  - `strong_keywords`
  - `weak_keywords`
  - `exclude_keywords`
  - `examples`
- `keywords` 用中文逗号或英文逗号分隔
- 其他可选关键词字段也用中文逗号或英文逗号分隔
- `state` 只能是：`idle` / `writing` / `researching` / `executing` / `syncing` / `error`
- 优先把“用户真的会说的话”写进 `keywords`
- `strong_keywords` 只放“命中后几乎不该错”的短句
- `weak_keywords` 只放有参考价值、但单独命中会有歧义的词
- 桌面系统操作优先写完整短句，不要只写“文件 / 目录 / 路径”这种过泛单词
- 如果一个任务特别关键，就单开规则并给更高 `priority`，不要塞进大杂烩
